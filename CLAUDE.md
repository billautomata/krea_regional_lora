# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A ComfyUI custom node package for the Krea2 / Flux.2-Klein single-stream DiT. It places multiple trained character LoRAs into one generated image, each confined to its own spatial region, without merging their weights (which would blend identities together). It works around a crash in ComfyUI's native LoRA-patch path on fp8 Krea2 models (`'Linear' object has no attribute 'weight_scale'`) by injecting LoRA deltas as forward-hook activations instead of patching quantized weights.

Four nodes are exposed, all under `conditioning/regional`, all one class hierarchy:
- `Krea2RegionalCharacterLoRA` — 2 zones (A/B), 1 LoRA each. The base class; everything else subclasses it.
- `Krea2RegionalCharacterLoRA3` — `ZONES = ("a","b","c")`.
- `Krea2RegionalCharacterLoRAStack` — 2 zones, up to `_STACK_SLOTS` LoRAs each; overrides `_build_stacks` + `INPUT_TYPES`.
- `Krea2RegionalCharacterLoRAStack3` — the Stack class with `ZONES = ("a","b","c")`.

Zone count is a class attribute (`ZONES`), never a constant in the mask code — the mask functions all take the zone list/count. Adding a variant should be a subclass with a different `ZONES`/`WRAPPER_SUFFIX` plus a registration, nothing more. Backward compatibility with saved workflows is explicitly NOT a constraint on this repo (the owner regenerates graphs); don't spend effort preserving widget names or slot indices.

Every node also takes an optional second `MODEL` (`model_b`) and returns two — one node configures both stages of a two-pass workflow (e.g. Krea2Raw then Turbo) from one set of widgets. Per-pass settings are deliberately not offered; use two nodes for that.

## Commands

There is no build, lint, or automated test setup in this repo — it's a pure-Python ComfyUI plugin loaded directly by ComfyUI at startup.

- **Syntax-check after edits**: `python3 -c "import ast; ast.parse(open('__init__.py').read())"`
- **Verify a LoRA/UNet pairing before wiring the node** (pure stdlib, no GPU, no ComfyUI needed — only parses safetensors headers):
  ```
  python_embeded\python.exe ComfyUI\custom_nodes\regional_character_lora\recon_krea2.py ^
      --unet "models\unet\<file>.safetensors" --lora "models\loras\<file>.safetensors"
  ```
  Answers whether the UNet uses fused `qkv` or separate `q/k/v` projections, whether the LoRA targets attn-only or attn+MLP, and whether it's a standard LoRA (`lora_up/down` or `lora_A/B` — supported) vs LoHa/LyCORIS (`hada_w1_a` — **not** supported by this node's `up @ down` injection path).
- **Zone/feather/strength tuning table**: `python test_masks.py --report` — regenerates the measurements in `docs/TUNING.md`. Run it before writing any number about mask strength into a tooltip, doc, or answer; the guidance there was wrong once because it was reasoned instead of measured.
- **Mask-math self-check** (pure torch, no GPU/ComfyUI/LoRA files): `python test_masks.py` — covers the N-zone split, zone ordering, the undefined-zone complement rule, and that 2 zones still match the old half/half math exactly.
- **Actually verifying the rest**: there's no full harness; runtime changes are verified by restarting ComfyUI, running a generation, and reading the `[RegionalCharacterLora]` console output (see below). Requires a GPU and Krea2 checkpoint — cannot be done from this environment alone.

## Architecture

Everything lives in `__init__.py` (single file by design — don't split it without reason). The pieces, in the order you'd trace a request:

**1. Mask/grid math (module-level functions).** Pure-tensor helpers with no ComfyUI dependency: `_build_token_grid`/`_resolve_grid` derive the `rows x cols` token grid from the *actual* runtime latent shape (`H//2, W//2` — Krea2 VAE is f8, patch size 2), never from a typed canvas size. `_smoothstep_ramp`, `_rect_token_mask`, `_masks_from_grid`, `_masks_from_boxlist`, `_masks_from_regions` each build a soft-edged **list** of per-zone masks (in zone order) over that grid from a different source (geometric split, bbox rectangle, JSON region list). `_masks_from_grid` cuts N equal slices as the plateau between two smoothstep boundaries, which reduces exactly to the old ramp/`1-ramp` pair at N=2. `_apply_blend` interpolates between a clean split and an even `1/N` merge. `_complement_the_one_gap` is the shared rule every mask source uses for undefined zones: exactly one gap gets the complement of the others, two or more gaps stay empty (ambiguous).

**2. `_RegionalSession`** is the runtime engine every node class delegates to. Constructed once per `apply()` call with `stacks` — an ordered `{zone: [(matrices_dict, strength), ...]}` dict whose key order IS the geometric slice order — plus `mask_ins` (`{zone: MASK|None}`) and the split config. A zone with an empty stack still occupies its slot, so an unfilled B doesn't shift C's slice. Two-phase prep, run every forward call via a registered ComfyUI model wrapper (`add_wrapper_with_key(..., WRAPPER_KEY, wrapper)`):
  - `_prepare_weights` (once): moves each matched LoRA's up/down matrices to device + bf16.
  - `_prepare_grid` (every call, but skips the rebuild if the latent shape is unchanged from last call): re-derives the token grid and masks from the *current* latent. This is what makes `auto`/`vertical_auto`/`horizontal_auto` track the real resolution even across a resolution change mid-session (e.g. a hires-fix second pass reusing the same patched model) — do not reintroduce a "prepare once and cache forever" pattern here, that was a real bug.
  - `_build_layer_map` matches each stacked LoRA's target-module names to live `nn.Linear` modules by a normalized signature (`_norm` — strips `lora_unet_`/`diffusion_model.`/etc. prefixes, collapses `.`/`_`, then applies `_SIG_RENAMES`, a diffusers→native rename table mirroring `comfy.utils.krea2_to_diffusers`, so both native-keyed and diffusers-keyed Krea2 LoRAs match). This is what makes the node "self-discovering": it never hardcodes fused-vs-separate qkv or which layers a LoRA targets. It warns when some LoRA targets matched no layer. If layers don't match, check with `recon_krea2.py`, not by hardcoding names here.
  - `_full_mask` builds the full text+image sequence mask per hooked layer, assuming image tokens are the **trailing** block (`[text | image]`) and the text-token count is `seq_len - n_image_tokens`, measured fresh from the real activation shape at each hook call — not a hardcoded constant. The text prefix gets `text_strength` (default 1.0 — both sides' deltas also transform the shared text tokens, matching what a global LoRA load does to the trigger-word pathway; 0 restores the old image-tokens-only behavior, which is much weaker for likeness LoRAs). Layers whose sequence has no image tail (the `txtfusion`/`tmlp`/`txtmlp` conditioning stack, which trained Krea2 LoRAs do target) run uniformly at `text_strength`, with a console note.

**3. The forward hook (`_make_hook`/`_stack_delta`)** — registered as a `register_forward_hook` on every matched `nn.Linear` for the duration of one `executor(...)` call, then removed. For each zone, it sums the `(x @ down.T) @ up.T` delta of every LoRA stacked on that side, multiplies by that side's full-sequence mask *once*, and adds the result to the layer's real output. This is the actual "regional injection" — LoRA deltas are never merged into weights, so both identities can coexist without bleeding.

**3b. Zone isolation (`isolate_zones`, default ON — `_run_isolated`/`_blend_isolated`/`_upsample_weight`)** — the hard-containment mode. The single-pass hook above cannot contain a LoRA's text-side effect: the prompt tokens are one shared copy that every image token reads through attention, so any per-token mask either transforms them (leaks everywhere) or doesn't (weak likeness) — and LoRAs targeting the `txtfusion`/`tmlp`/`txtmlp` stack have no image tokens to mask at all. Isolation sidesteps this by running the model once per non-empty zone with only that zone's LoRAs hooked at a **uniform** full-sequence mask (`_uniform_mask`: image tail 1.0, text prefix `text_strength` — i.e. each pass is exactly a global LoRA load), then compositing the *outputs* with the zone masks upsampled to latent resolution, where every value has coordinates. If the masks sum to ~1 everywhere it's a normalized weighted sum (N passes); otherwise a clean no-LoRA pass runs as the baseline and each zone contributes `weight * (out_z - clean)` (N+1 passes — handles gaps and overlaps). Cost is one extra full model pass per zone; that's the price of containment, don't try to optimize it back into one pass. Zones run sequentially — batching them into one call is the known upgrade path if step time matters.

**4. Mask source precedence** (`_RegionalSession._build_masks_now`): painted `mask_a`/`mask_b` MASK sockets (if wired) always win → else `manual` uses the JS visual editor's `regions` JSON, falling back to `auto` if nothing's been drawn → else `bbox` uses an external `BOUNDINGBOX` wire (e.g. from KJ nodes), falling back to `auto` if nothing's wired → else the geometric `auto`/`vertical_auto`/`horizontal_auto` split. `auto` (`_resolve_auto_split`) picks `vertical_auto` (left/right) for landscape latents and `horizontal_auto` (top/bottom) for portrait/square, matching a side-by-side composition — `vertical_auto`/`horizontal_auto` selected explicitly bypass this heuristic entirely. This heuristic is zone-count-agnostic **on purpose**: a portrait 3-zone latent gives top/middle/bottom. Don't add a zone-count special case here.

**5. `web/regional_lora.js`** — a ComfyUI DOM canvas widget (`app.registerExtension`) that replaces the auto-generated `regions` string widget with a draggable one-box-per-zone editor (only meaningful when `split_mode = manual`). It writes normalized `[{char:'a'|'b'|'c', x,y,w,h}, ...]` JSON that `_masks_from_regions` consumes. `nodeZones()` derives the box count from the node's OWN widgets (`lora_a` or `lora_a1`), so a new zone count needs no table here — but the node name still has to be added to the `nodeData.name` guard at the top of `beforeRegisterNodeDef`. There is no add/delete-box UI, so the default layout IS the box count.

**6. Node classes** are thin and zone-driven: `INPUT_TYPES` generates LoRA slots per `ZONES` entry then appends `_common_widgets`/`_optional_widgets`; `apply()` calls `_build_stacks` (the only method subclasses override for slot shape), bakes it **once** with `_bake_stacks`, then builds one `_RegionalSession` per wired model and hands each to `_install()`. `apply()` takes the per-zone widgets via `**kw`, so ComfyUI must call it with keyword args (it does).

**7. Two models, one config.** `model` and `model_b` each get their own `_RegionalSession` because a session caches direct references to one model's `nn.Linear` objects — reusing a session across models would inject into the wrong one with no error at all (`test_two_models_hook_their_own_layers` exists for exactly this). What they DO share is the `_bake_stacks` output: the same entry dicts, so `_prepare_weights` moves each LoRA to VRAM once, not per model. That sharing is load-bearing and easy to break — `_side_maps` used to rebuild the dicts per session and silently doubled VRAM; the test asserts `da is db`. `_prepare_weights`/`_weights_prepared` are keyed on device so a second model on another device re-moves rather than using the first's tensors.

**8. Reference backdrop** (`show_reference`) is **entirely frontend**: Python declares the boolean and does nothing else — no IMAGE input, no temp write, no `ui` return. `regional_lora.js` subscribes to the graph-wide `executed` event, keeps the last output that carried `images`, and pushes it to every editor with the flag on. There is no image input **on purpose**: the picture worth showing is produced downstream of the MODEL this node outputs, so a link back in is a **dependency cycle** and ComfyUI rejects the prompt. That was built once and failed exactly that way — do not re-add a socket.

Hit-testing order matters: `onDown` tests **every** region's resize handle (topmost first) before testing any region's body, and `draw` paints handles in a matching second pass on top of all box bodies. With a single interleaved pass an overlapping box swallows the one underneath's corner and the region becomes impossible to resize — you'd have to shrink everything and place the boxes one at a time. Don't collapse those loops back together.

Aspect handling: `getMinHeight()` returns `width * imageAspect` with **no clamp** when a backdrop is loaded, so the widget takes the image's shape and `drawImage` fills it exactly. The old `Math.min(…, 460)` cap is what stretched it. Region boxes stay in whole-canvas 0..1 coordinates and are NOT remapped — the boxes are set manually and must never move on their own; fix aspect by sizing the widget, never by transforming box coordinates. Flag off = no file written, no fetch, no `ui` key. PIL/numpy are imported *inside* `_reference_ui` on purpose — the module must stay importable with only torch+safetensors so `test_masks.py` can run anywhere. The whole path is wrapped in try/except and fails to a plain backdrop; the frontend half is the fragile part (unofficial `onExecuted`/`app.nodeOutputs` shape), which is why it's default-off.

## Known sharp edges (by design, not yet hardened)

- LyCORIS/LoHa/`diff`-only files still aren't supported (`_load_lora_matrices` only recognizes `lora_down/up` and `lora_A/B` keys), but loading one now prints a loud "no effect" warning instead of failing silently.
- Rect masks (`manual`/`bbox` modes) are peak-normalized to 1.0 — the raw sigmoid product tops out well below 1 for boxes smaller than ~half the canvas, which used to silently weaken the LoRA inside its own region.
- `text_strength` applies BOTH sides' deltas to the shared text tokens — that's the identity-strength/bleed tradeoff knob, not a bug. **Only relevant with `isolate_zones` OFF**; isolation removes the tradeoff entirely (each zone gets its own pass, so bleed is impossible and `text_strength` 1.0 just means "full-strength LoRA"). It is unrelated to the `clip` strength on stock LoRA loaders (that patches the separate text-encoder model; this stays entirely inside the diffusion model).
- Rect masks feather across the canvas edge, so the outermost token row/column of a full-bleed `manual`/`bbox` region sits near 0.5 rather than 1.0.
- A 3-zone Stack node doesn't exist yet; it's `ZONES = ("a","b","c")` on a `Krea2RegionalCharacterLoRAStack` subclass plus the node name in the JS guard.
- `text_strength` scales with zone count in the direction opposite to intuition: **more zones need MORE, not less**. `seam_feather` is a fraction of the whole axis, so N zones have N-1 seams and 2(N-1) feathered edges eating the plateau — at the default 0.08 feather a 2-zone split keeps ~43%/42% of the image at full strength, a 3-zone split only ~26%/18%/25% (the middle zone is soft on both sides). Fewer full-strength image tokens per identity means the shared text pathway carries more of it. Confirmed on real generations: 1.0 for 2 zones, ~2.0 for 3. The widget max is 4.0 for that reason. Do NOT "fix" this by auto-scaling feather or text_strength by zone count — it would be invisible behavior and it changes existing 2-zone graphs. Full write-up with the measurement table: `docs/TUNING.md`.
